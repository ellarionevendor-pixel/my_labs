# Lab 24: Exploiting XSS to Bypass CSRF Defenses

## Objective

The goal of this lab was to exploit a stored XSS vulnerability in the blog comments section to steal a victim's CSRF token and use it to change their email address.

## Analysis

1. **Finding the CSRF token:**
   - Inspected the account and comment-related forms and found that the CSRF token was stored in a hidden input field named `csrf`.
   - Since the blog comments section was vulnerable to stored XSS, injected JavaScript could access the page's DOM and read this token.

2. **Stealing the token:**
   - Created a script that waits for the `DOMContentLoaded` event to ensure the page has finished loading.
   - Retrieved the token using `document.getElementsByName('csrf')[0].value`.
   - Submitted the stolen token as part of a new blog comment.
   - This allowed the token to be retrieved later from the comments section.

3. **Changing the victim's email:**
   - Used the stolen CSRF token in a POST request to `/my-account/change-email`.
   - The request included the new email address and the token.
   - Because the JavaScript executed in the victim's authenticated browser context, the request used their existing session.

## Exploitation

The attack involved two scripts:

- `get-csrf-token.js` read the victim's CSRF token from the hidden input and submitted it as a new comment. The comment acted as a way to retrieve the token.
- `change-email-csrf.js` used the retrieved token to send a POST request to the email-change endpoint.

The token was obtained from the victim's page rather than generated by the attacker. This made it possible to satisfy the application's CSRF validation.

## Result

Successfully bypassed the CSRF protection by chaining stored XSS with CSRF token theft. The injected script retrieved the victim's token and used it to change their email address.
